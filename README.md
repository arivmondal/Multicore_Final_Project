# CUDA Low-Rank Filtering Demo

This repository now includes a Django web app that wraps the existing filtering code paths:

- `person1`: exact full-kernel CUDA baseline through CuPy/OpenCV
- `person2`: low-rank CUDA fused pipeline through `lowrank_svd(.exe)`

The web UI is built for live demo use. It lets you upload an image or choose a bundled sample, run the baseline and low-rank paths side by side, inspect quality and performance metrics, and launch a rank sweep benchmark without leaving the page.

## Existing Entry Points

- `person1/src/convolution_runner.py`
  - `CudaExactConvolver`
  - exact 2-D CUDA convolution baseline
- `person1/src/metrics.py`
  - PSNR, SSIM, and error stats helpers
- `person2/src/main.cu`
  - `lowrank_svd`
  - kernel SVD analysis mode and fused low-rank filtering mode
- `person2/scripts/run_fused_filter.py`
  - Python wrapper around the low-rank CUDA binary
  - now supports RGB images and motion thickness from the web app
- `person2/scripts/generate_kernels.py`
  - Gaussian, disk, and diagonal-motion kernel generation

## Web App Structure

- `django_project/`
  - Django settings, URLs, WSGI/ASGI
- `demoapp/`
  - `views.py`, `forms.py`, `urls.py`
  - `services/filter_runner.py`
  - `services/benchmark_runner.py`
  - `services/kernel_factory.py`
  - `services/metrics.py`
  - `services/plotting.py`
  - templates and static styling

## Features

- upload an image or choose a bundled sample
- choose:
  - Gaussian blur
  - Disk blur
  - Diagonal motion blur
- set kernel size and approximation rank
- run:
  - exact full 2-D baseline
  - low-rank approximation
  - both
- inspect:
  - original image
  - baseline output
  - low-rank output
  - absolute difference heatmap
- view:
  - full runtime
  - low-rank runtime
  - speedup
  - image dimensions
  - detected device path
  - Frobenius error
  - relative Frobenius error
  - cumulative energy retained
  - MSE / PSNR / SSIM / max absolute difference
- run a benchmark rank sweep with plots and downloadable CSV

## Setup

Use the existing virtual environment if you already have one for the CUDA scripts.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-web.txt
```

If you need the low-rank CUDA binary on Windows, rebuild `person2` first so this file exists:

```text
person2\build\lowrank_svd.exe
```

The web app will still run without that binary, but the low-rank path will fall back to a CPU separable implementation and will report that in the UI.

## Run The Web App

From the repository root:

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

Then open:

```text
http://127.0.0.1:8000/
```

## Notes

- The UI uses HTMX for partial-page updates instead of a full frontend framework. (Mostly generated by GPT 5.4)
- The exact baseline prefers the existing CuPy CUDA path and falls back to OpenCV CPU filtering if CUDA is unavailable.
- The low-rank path prefers the existing `person2` CUDA wrapper and falls back to a CPU low-rank separable implementation if the binary is unavailable or fails.
- Runtime results include startup overhead from the current process state, so the first run can be slower than later runs.
- Generated demo artifacts are written under `demo_media/` and ignored by git (just make sure this is in your git ignore if about to push).
